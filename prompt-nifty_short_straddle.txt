Strategy & Execution Logic

2. VIX-Adaptive Strike Selection (09:19 AM)

Fetch Delta for all candidate strikes via the /v3/market-quote/option-greek endpoint using a single batched request: pass all candidate instrument keys as one comma-separated string in one API call. Do not loop per-strike — this endpoint is tightly rate-limited and a per-strike loop across the weekly chain will trigger HTTP 429 and stall the entry window.
Compute delta_band and premium_band as functions of entry_vix, not fixed constants:

Otherwise: use base MIN_DELTA / MAX_DELTA.
Conflict resolution rule (explicit): delta band is the primary filter; premium band is a secondary sort/tiebreaker, not a hard filter. If no strike satisfies the premium band within the qualifying delta range, select the strike with delta closest to the midpoint of the band and log a WARN: premium_band_unmet event. Never fall through to no-trade silently — either take the best-available strike under this rule or explicitly skip the leg and log why.
Core Short Legs: 1 CE and 1 PE per the rule above.
Hedge Long Legs: 1 OTM CE and PE closest to HEDGE_TARGET_PREMIUM. If no strike exists within HEDGE_PREMIUM_TOLERANCE, abort entry for that side entirely (do not enter an unhedged short) and log ABORT: no_valid_hedge.

3. Hedged Execution (09:19:30 – 09:20:30 AM)

Execute Hedge long legs first using LIMIT BUY (Ask + HEDGE_LIMIT_SLIPPAGE_TICKS).
Hedge fill timeout (new): poll order status for up to HEDGE_FILL_TIMEOUT_SEC seconds. If unfilled:
Cancel the pending hedge order.
Re-price once at Ask + HEDGE_LIMIT_SLIPPAGE_TICKS_RETRY and retry once.
If still unfilled after the retry, abort entry for that leg pair entirely, log ABORT: hedge_timeout, and do not place the corresponding core short leg. Never enter a naked short because its hedge failed to fill.
Once both hedge legs for a pair are confirmed filled, execute the corresponding Core short leg using MARKET SELL.
Parse the exact order_id and average_price from the Upstox JSON response; persist to an in-memory position ledger keyed by order_id (not by symbol alone, to survive re-entries).

4. Risk Management & Async Tick Engine

Connect to MarketDataStreamerV3.
Primary stop-loss — broker-side (corrected): NSE disallows SL-M (Stop-Loss Market) orders on options to prevent freak-trade executions; Upstox will reject an SL-M order for these instruments. Instead, immediately after each core short leg fills, place a broker-side SL-L (Stop-Loss Limit) order with trigger_price = fill_price * (1 + SL_PERCENT) and limit_price = trigger_price + SL_LIMIT_BUFFER_POINTS. The buffer must be wide enough to realistically execute in fast markets without being so wide it defeats the stop's purpose — treat SL_LIMIT_BUFFER_POINTS as a tunable, not a formality. This order is the authoritative stop and protects the position even if the local process, websocket, or network fails.
Local SL evaluation: continue to evaluate the same threshold locally on every tick as a faster-acting duplicate. If the local check fires first, cancel the broker-side SL-L and market-exit; if the broker-side SL-L fires first, detect the fill via order-update feed and reconcile the local ledger — do not double-exit. Because SL-L can fail to fill in a fast-moving/illiquid market (unlike SL-M), also treat a triggered-but-unfilled SL-L as a kill-switch-eligible condition: if triggered and not filled within SL_L_FILL_TIMEOUT_SEC, escalate to a market order.
Momentum re-entry: max MAX_REENTRIES_PER_LEG per leg. Re-entry is only permitted if entry_vix at re-entry time has not risen more than REENTRY_VIX_GUARD_PCT above entry_vix at original entry (prevents re-shorting into a vol spike). Wait for LTP < fill_price * (1 - REENTRY_MOMENTUM_DISCOUNT) before re-entering.
MTM definition (explicit, new): total_mtm is computed exclusively from live LTP marks from the streamer for every open leg (short and hedge), refreshed on every tick batch — not last-fill price. If a leg's LTP goes stale (no tick received for STALE_TICK_TIMEOUT_SEC), freeze that leg's contribution at its last known mark and flag DATA_STALE in the MTM log line so the kill-switch decision is auditable.
MTM Trailing: if total_mtm >= TRAIL_START_PROFIT, lock TRAIL_LOCK_PROFIT. Step up by TRAIL_STEP per TRAIL_STEP_INCREMENT of additional profit.
Kill-Switch: emergency close all if total_mtm <= MAX_DAILY_LOSS, or drops below the active trail lock, or on feed_disconnected_for > MAX_FEED_DOWNTIME_SEC (see below).
Feed disconnect handling (new): if the websocket disconnects, attempt reconnect with exponential backoff up to MAX_RECONNECT_ATTEMPTS. While disconnected, rely on the broker-side SL-M orders already in place as the safety net. If disconnected longer than MAX_FEED_DOWNTIME_SEC, trigger the kill-switch via REST (square off all open positions via market orders), independent of the websocket.
Time Exit: 15:15 PM emergency exit via REST market orders, cancel any resting SL-M orders after confirmed square-off.

2. Async Race Condition Prevention

No blocking HTTP calls (requests.post, order placement, etc.) inside on_tick.
Do not merely wrap the synchronous requests library in asyncio.create_task() — requests is blocking I/O, and scheduling it as a task does not make it non-blocking; it will still stall the event loop and cause websocket lag/disconnects during order placement. Instead, choose one of:
Use aiohttp for all REST calls issued after the websocket connects (preferred), or
Run requests calls inside loop.run_in_executor(None, requests_call) so they execute on a separate thread and don't block the event loop.
Route all order dispatch (new orders, SL-L placement, cancels, re-entries) through an asyncio.Queue worker built on whichever of the above is chosen, so the websocket stream never lags or disconnects while waiting on broker confirmations.
Order-status polling (hedge fill timeout, SL-L fill timeout) must also use the non-blocking approach and never block the tick loop.

3. API Strictness

v2 exclusively for order placement and option chain REST queries.
v3 exclusively for MarketDataStreamer.
No mixing of v1 endpoints anywhere.

4. Paper Trading & Graceful Shutdown

PAPER_TRADING_MODE = True is the mandatory default for every run of this script. The script must never place a real order unless a human has manually edited this constant to False in the source file — there is no runtime flag, CLI arg, or environment variable that may switch this. Treat flipping it to False as a deliberate, separate act from running the script.
Wrap the main execution loop in try...except...finally. On KeyboardInterrupt or fatal exception with PAPER_TRADING_MODE == False, automatically fire the emergency square-off function before the process exits — verify this path is reachable even from unhandled exceptions in the async event loop (e.g., via loop.set_exception_handler or a top-level asyncio.run wrapper), not only from synchronous except blocks.
If PAPER_TRADING_MODE == True: bypass REST order endpoints, log the exact JSON payload that would have been sent, and simulate a fill using PAPER_SLIPPAGE_MODEL_BPS applied against the current tick price (not the raw tick price) so paper results aren't unrealistically clean.
